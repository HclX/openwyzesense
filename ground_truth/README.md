# Ground truth

Raw evidence behind `docs/FACTS.md`. Files here are never edited; `SHA256SUMS` lists every file
(`test_checksums` verifies it). Only `decoded_frames.jsonl` files are derived, see below.

**What the public repository leaves out.** Two kinds of evidence are listed below but not published:
- the stock firmware dumps in `firmware/` (Wyze's and TI's code: dump your own device with `tools/dongle_sbl.py
  backup` or `tools/uniflash.py backup`). Their CCFGs and NV pages are test vectors in `reference/tests/vectors/`
  (`ccfg/`, `nv/`), configuration and sensor tables rather than code;
- the longer recordings of everyday traffic in the user's house (`host/2026-05-21_house_dongle_778B5F63/` and the
  `rf/` sessions marked so below), which show its daily routine. The short sessions recorded around a deliberate
  action (a pairing, a button press) and everything on the test networks are published.

Their SHA-256 sums are in `SHA256SUMS.unpublished`. The tests that need one of them skip without it; with a full
copy, `OWS_GROUND_TRUTH=<its ground_truth/>` runs them all (`reference/tests/gt.py`, and the `nvstore` C test).
Two log files had local file system paths in Python tracebacks replaced by `<repo>/` and `<scratch>/`.

Per session:

- `*.cu8`: for `-S` sessions, rtl_433's own clips (`gNNN_…`); `rtl_433.log` maps each file to its detection time.
  For `-w` stream sessions the full stream was too large to keep; `snip_HHMMSS_mmm.cu8` are slices of it, named
  by the local time of the first burst of interest; each slice starts 0.1–0.2 s before that time.
- `start_time.txt` / `stop_time.txt` (streams): Unix time written just before rtl_433 was started / after it
  stopped. Sample *n* of the stream is at about start + n / fs; in the 07:30 session frames appear ~1 s
  earlier than this predicts relative to the bridge, so the start stamp leads the first sample by up to ~1 s.
- `bridge_events.jsonl`: the user's bridge state for each sensor, logged on each push from the bridge.
  `received` (or `polled`) is the local receive time; `last_seen` comes from the dongle's clock and lags real
  time by 11–23 s, so it is not used for timing. `initial: true` rows are the snapshot at logger start.
- `decoded_frames.jsonl` (**derived**, `tools/decode_stream.py` for sessions from 22:36 on): our decoder's output over the *full* stream or capture, one JSON line
  per frame: time `t` (from start_time + sample / fs), `psdu` (MAC frame + 4-byte FCS, hex), `crc_ok`, and
  parsed MAC header fields. For the stream sessions this is the only record of frames outside the kept slices.
  Each PSDU with `crc_ok: true` carries its own CRC-32, so its content is self-checking.
- `devices.json`: the bridge's device inventory (2026-10-21).
